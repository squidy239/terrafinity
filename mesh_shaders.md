# Mesh renderer strategy (mesh-only)

Mesh-only decision: single task+mesh pipeline, no vertex fallback to maintain; drops Apple/MoltenVK until mesh-shader support lands there. Merged from the VRAM-reduction, waves/clouds-dynamic-voxel, and mesh-shader sketches (source: ideas.md): face payload format first, then the task+mesh pipeline, then procedural dynamic content.

## VRAM reduction for mesher designs (deep)

Grounding: ChunkSize=32; CPU Mesher emits packed-u64 Faces (16-bit block_type Tag + greedy z/y/x lengths + xyz + FaceRotation side) split opaque/transparent; GPU path uploads each visible face as one 8 B uvec2 instance (face_stride=8, MeshBuffer face_offset/face_byte_count/face_count, GpuRegionAllocator + MeshUploader staging ring + retired-face-buffer reclamation) expanded to a 4-vert tristrip in the vertex/shadow shaders via face_decode.glsl, drawn per-chunk through MeshCandidate (32 B) / MeshData (48 B) indirect draws culled by cull.comp (frustum + Hi-Z, early/late + shadow slots). Textures today are per-Block bindless combined-image-sampler images (TextureManager, update-after-bind + partially-bound, one sampler, nearest mag / linear min, full mip chains per block). CPU side, chunks live in a tiered cache hierarchy (SetAssociativeCache shards via Cache.zig, EntityRegistry queue-as-authority + bounded resident tier + save-flag spill, WorldStorage RocksDB+zstd for disk) with LOD levels (chunk_level, levelToBlockRatioFloat) and MeshUploader admission-mutex backpressure. So VRAM pressure comes from four places: face payload bytes, candidate/indirect bookkeeping per mesh, texture bytes, and residency (how many chunks stay GPU-resident vs evicted to RAM/disk).
| # | Method | How it saves VRAM | Fit for this pipeline | Cost / risk |
|---|--------|-------------------|----------------------|-------------|
| 1 | 16-bit / local-quantized face payloads (positions in 5 bits/axis + lengths in 5 bits/axis, header-deduped) | Voxel coords are grid integers 0..31, so xyz needs 5 bits/axis (15 bits total) and greedy lengths need 5 bits/axis; a face already fits far below 64 bits once block_type is factored out. Bucketing by FaceRotation x opaque/transparent lets one meshlet/chunk-direction carry a single block_type+side header so each face body drops to ~16 bits (position + 2 in-plane extents; the normal-axis coordinate and out-of-plane length are header-constant). Typical cut: 8 B -> 2-4 B/face, i.e. ~2-4x on the dominant buffer | Best first step: Mesher already emits axis-aligned greedy quads with FaceRotation known, so the bucketing is a CPU regroup, not a new algorithm; face_decode.glsl gains a header-fetch + bit-unpack path while the current uvec2 path stays as fallback; exact (lossless, grid-aligned) so zero crack risk unlike float quantization | Small CPU regroup + shader unpack ALU; header indirection complicates the per-face instance layout (mesh shader or a compute-expansion pass fits it best; on the vertex path it is one extra buffer fetch per draw, not per vertex, if headers are per-meshlet constants) |
| 2 | Header-deduped face payloads (per-meshlet block_type+side+plane header, face bodies carry only in-plane data) | Removes the two most redundant fields: block_type (u16 today, but only ~9 visible blocks => 4 bits entropy) repeats across every face of a uniform region, and side/plane repeats across every face of a directional bucket. One header per (direction x block-run) amortizes ~19 bits over dozens-hundreds of faces; combined with method 1 this is what gets bodies to 16 bits | Structural match for the ~12 meshlets/chunk (FaceRotation x opaque/transparent) design in the mesh-shading section: each meshlet header IS the dedup point (block_type + side + opaque flag + face count), bodies are pure 2D rects. Also composes with the existing opaque/transparent split (transparent faces already separated in Mesher.mesh) | Variable-length bodies per meshlet need a (offset,count) index alongside MeshCandidate.face_offset/face_count; CPU mesh must emit headers + bodies in one pass; measure header overhead on sparse meshlets (a 1-face meshlet pays a full header, net loss) before forcing tiny buckets |

Quantization + cache/fetch optimization must come before encode for the ratio to materialize | Partial fit, adopt selectively: our faces are quads-as-instances, not indexed triangle soup, so meshopt_buildMeshlets clustering and vertex-cache optimization buy little (no post-transform reuse across quads; greedy merger already minimized count). GPU-side meshlet decode (meshletdec.slang pattern) only matters if a mesh-shader path lands | CPU decode per mesh at upload time (GB/s, off the frame thread via the existing drain task); adds a dependency + a second on-GPU layout if GPU-decode is also built; must not fight the admission-mutex all-or-nothing reservation (decode before reserveUpload, never while holding staging slices); marginal until faces exceed ~4 B (do 1+2 first, then measure) |
| 4 | Texture consolidation: atlas vs array vs current bindless-per-image (+ BC7/ASTC/Basis) | Textures dominate VRAM once geometry is greedy-merged: per-block images each carry a full mip chain (~1.33x base) plus per-image alignment slack. A 2D array (one layer per block, single mip chain accounting, one descriptor) or a packed atlas (one image, one chain) removes slack and descriptor count; block-compressed formats (BC7 fixed 8 bpp ~4:1 vs RGBA8, ASTC tunable 4x4..12x12 blocks for flat voxel colors) cut bytes ~4-8x at load via Basis Universal/KTX2 transcode (ship one .basis, transcode to BC7 desktop / ASTC mobile) | Careful: current TextureManager is already bindless (update-after-bind + partially-bound, nonuniform index by block id), which the 2026 consensus favors over atlases for voxel engines (no bleed, no same-size constraint, no descriptor churn). So do NOT regress to a naive atlas (mip bleed across block borders needs padding/custom UVs; arrays force uniform size/mips). The real win here is orthogonal: keep bindless layout, compress the CONTENT (BC7/ASTC via Basis) and consider a 2D array only if per-image overhead or descriptor limits ever bind (block count is ~9 visible today, so neither binds yet) | Transcode pipeline at pack-load (Basis -> BC7/ASTC) + format feature detection; BC7 needs sRGB-correct sampler/format handling adjacent to existing gamma_correction path; ASTC block-size tuning per texture (flat colors coarser, hero detail finer); atlas option rejected unless block count explodes past bindless limits |
| 5 | Sparse binding / residency (VK sparse images/buffers, shaderResourceResidency fallback to coarser LOD) | Virtual address space far larger than physical backing: bind VkDeviceMemory pages only for in-view / needed-LOD chunks (or texture tiles), unbind on eviction via batched vkQueueBindSparse; shaders check residency and fall back to a coarser resident LOD instead of popping. In theory the only design that makes VRAM sublinear in world size | Poor fit now, deferred: driver behavior for vkQueueBindSparse is vendor-variable (latency/stutter on frequent rebind), granularity comes from vkGetImageSparseMemoryRequirements2 (may not match 32^3 chunks), and the engine already HAS a working software residency system (cache tiers + LOD levels + RocksDB spill). Software pool management (method 6) gets most of the benefit with none of the driver risk | High: sparse queue family support checks, batched bind protocol, residency-aware shaders, VK_EXT_memory_budget/memory_priority integration, early hardware stress test mandatory; do not build unless software eviction provably cannot keep up |
| 6 | Streaming + LOD eviction through existing cache tiers (the recommended residency backbone) | No new API: bound VRAM by policy, not by format. Resident set = f(distance, visibility, LOD): MeshUploader retired-face-buffer reclamation + region free (freeMesh/processRetiredFaceBuffers) already frees GPU bytes on timeline; SetAssociativeCache/Cache.zig shards + EntityRegistry spill give the eviction pattern (LRU-ish victim, save-flag writeback); WorldStorage RocksDB+zstd is the cold tier; LOD levels (chunk_level, levelToBlockRatioFloat, effectiveMinChunkSize precedent in shadows) shrink far chunks ~8x per level. Compact indirect draws (method 7) so evicted slots cost no GPU work | Best architectural fit: every primitive exists and is already load-bearing (admission-mutex backpressure, drain task + publishPending split, Hi-Z + frustum cull skipping evicted/invisible chunks). Work is policy + bookkeeping: per-chunk LOD selection, eviction priority (distance + visibility_buffer + shadow need), and keeping the CPU-mapped candidate array writes inside beginFrame's GPU-idle window | Policy tuning (hysteresis to avoid evict/re-mesh thrash at LOD boundaries; stale-id drop discipline from EntityRegistry); background-task threading discipline (record Publications, never touch candidates off the frame thread); needs method 7 so freed slots do not leave zero-instance draws behind |
| 7 | Indirect-draw compaction (cull-then-compact in cull.comp: atomics/prefix-sum into a dense draw list, vkCmdDrawIndexedIndirectCount style) | Saves the hidden VRAM-adjacent cost: without compaction every resident chunk owns indirect slots x gpu.slot_count (early/late + shadow) even when culled, and zero-instance draws still consume command-processor cycles + MeshData/indirect buffer footprint sized for the worst case. Compaction turns the sparse candidate array into a dense active list so buffer sizing and GPU work scale with VISIBLE meshes, which is what lets method 6 evict aggressively without leaving dead slots behind | Direct extension of today's cull.comp (which already writes out_indirect/out_meshes + count buffer per slot): add a compact pass (per-thread visible flag -> prefix-sum/AtomicAdd slot assignment -> dense VkDrawIndirectCommand + MeshData writes) or rewrite in place with DrawCount. MeshCandidate.face_count==0 gating already exists as the zero-draw seed; compaction is its generalization | Prefix-sum vs atomics tradeoff (atomics simpler, prefix-sum more deterministic under contention); count-buffer + DrawCount API path needs capability checks; barrier discipline between cull-write, compact, and draw (the existing cullDrawBarrier is the template); keep per-slot layout (MeshData 48 B) stable so shadow + early/late consumers do not fork |
Recommendation: do 1 then 2 (exact, lossless, biggest B/face win, no HW gating) with the uvec2 decode deleted once the mesh path reads the packed bodies at parity (mesh-only — no kept fallback); build 6 as the standing residency policy (it is mostly wiring existing tiers + LOD selection + eviction hysteresis) and 7 alongside it so eviction actually removes GPU work; compress texture CONTENT via Basis->BC7/ASTC inside the existing bindless layout (method 4's content half) and reject the atlas/array migration until block count or descriptor pressure forces it; use method 3's codecs only on the face-body stream after 1+2, skipping meshopt clustering; defer 5 (hardware sparse) until software eviction is proven insufficient. Rough order-of-magnitude: 1+2 cut face bytes ~2-4x; BC7/ASTC cut texture bytes ~4-8x (the larger absolute win once geometry is merged); 6+7 bound total VRAM to the visible set instead of the loaded set, which dominates everything at planet scale.

## Mesh shaders

Mesh-only decision (no second pipeline to maintain): single task+mesh pipeline; drops Apple/MoltenVK until mesh-shader support lands there.

Grounding: ChunkSize=32 (CoordInChunk 5 bits/axis). CPU Mesher.zig emits packed-u64 Faces (16-bit block_type + z/y/x greedy lengths + xyz + FaceRotation side) split opaque/transparent (water never merges); faces upload via MeshUploader.reserveUpload (admission-mutex + staging ring) into MeshBuffer regions, drawn per-chunk through MeshCandidate/MeshData indirect draws. The mesh pipeline replaces vertex expansion (face_decode.glsl: anchor + u_len/v_len + face_axes/face_swap/face_sign tables) and cull.comp (frustum + Hi-Z, early/late + shadow slots) with mesh expansion + task-shader culling; both deleted at parity.

Plan, in order (max-perf objective):

1. Bitmask-row greedy mesher interior: rewrite addGridFaces as u32-row bitmask sweep (ChunkSize=32 = 1 word/row; faces via shift/XOR of adjacent plane masks; runs via trailing-zero walks; y-merge as mask-AND across rows; water as masked-out bitplane; emit-time inline fill into direction buckets). Same Faces out, zero GPU change; row-major runs feed Morton bodies + weld maps + occluder sort with no regroup pass, and cut remesh CPU ~4-16x on the reserveUpload latency path.
2. Direction-major buckets (~6-12/chunk) with Morton-delta bodies (~10b/face, restart anchors every 8 faces keep decode parallel) + flag-gated corner-index sharing (weld only buckets with sharing >20%, zero-tax flat path otherwise). One forward-compatible header per bucket (side:3b + block_type + base xyz + AABB + exact normal + task idx+ptr ~8B). Cuts face bytes ~5x; doubles as the VRAM-reduction win.
3. Mesh-shader-only first, ballot-compacted: one thread per quad, 4 verts + 6 idx; subgroup ballot + exclusive-add packs survivors densely, turning orientation/depth kills into ~2.5x fewer mesh invocations (a quad is always 4 verts regardless of size — greedy scale-invariance beats 64v/126t triangle packing); port face_decode verbatim. Single-variable cutover with cull.comp guarding, then delete both.
4. Task shader next, profiler-gated per class: exact-normal backface kill (~50% for 1 dot/meshlet) + Hi-Z occlusion with front-to-back meshlet sort preserved end-to-end (sort order is what makes Hi-Z multiply) + shadow cascade caps (emit only >1px light-space quads mid/far, ~25-30% whole-frame mesh ALU, invisible in shadow space) + region-batched DrawMeshTasksIndirect(Count) only for uniform depth-coherent regions via sorted index (gated; per-chunk elsewhere; gate must survive the sorted index being rebuilt per slot since early/late/shadow counts differ — else per-chunk + P4 bypass). Per-class bypass where profiling shows loss; gl_CullPrimitiveEXT in mesh for depth/prepass only.
5. Dynamic voxel art (clouds / waves / grass / animals): see `Dynamic voxel art` below — grid-aligned seeds + limb-vector traces replace this step's crossed-quad/billboard sketch.

Notes: profiler-gating rules all of step 4's later clauses + any further codecs. Literal meshopt clustering stays out (no post-transform reuse across quad-instances). Instrument from day one with TASK/MESH_SHADER_INVOCATIONS + MESH_PRIMITIVES_GENERATED on NV + AMD + Intel; task tuning is vendor-sensitive.

## Waves clouds dynamic voxels (deep)

Grounding: ChunkSize=32; CPU Mesher emits packed-u64 Faces (16-bit block_type + greedy lengths + xyz + FaceRotation side) split opaque/transparent, and water never merges (addGridFaces rule); GPU path uploads each face as one 8 B uvec2 instance (face_stride=8) expanded in vertexshader.vert via face_decode.glsl, drawn per-chunk through MeshCandidate/MeshData indirect draws culled by cull.comp. Upload path is MeshUploader.reserveUpload under admission_mutex (StagingRing.allocPair atomically, FIFO retire stalls at first unbound entry, so a held-but-unbound slice wedges the ring) with the drain task recording Publications applied later by publishPending in the frame thread's GPU-idle window (beginFrame timeline throttle proves the graphics queue idle before touching scene.persistent.mapped). World has LOD levels (chunk_level, levelToBlockRatioFloat), cache tiers + RocksDB+zstd cold tier, and an EntityRegistry update queue (authoritative live-id list, cache as bounded resident tier, eviction spills via save flag). Any per-frame voxel animation must survive this pipeline: remesh cost, staging-ring pressure, candidate-window safety, and LOD/eviction coherence.

| - | ------ | ------------ | --------------------- | ---- |

Clouds -> ship 5 (scrolling shell + weather map), graduate to 7 (Nubis-style march reusing the weather map) only when fly-through matters; reject 6-as-animated (drift-by-rewrite churns the ring for zero visual win over scrolling). Route all transient dynamics through 8. Hard rule underneath: per-frame animation must never allocate staging, remesh, or touch candidates — if it does, it is a tick-rate gameplay update, not animation.

## Dynamic voxel art — clouds, waves, grass, animals

Rule: voxels NEVER leave the grid. No rotated/translated cube verts — motion is integer-cell translation plus revoxelization from analytic sources only. (Rotation undecided — see bottom section; plan written as if out.)

Adopted stack, in dataflow order:
1. Seeds in: static seeds (cell xyz + type + phase ≈ 4-8B) uploaded once to side buffers outside Mesher authority; animals additionally pass limb vectors (segment start/dir/len/radius, dozens of vecs/animal) into a small persistent buffer per frame — negligible next to face traffic, never the staging ring. All motion = pure f(seed/vectors, GameTime): grass `cell_step = floor(noise × amp)` (top voxel steps over discretely), waves = noise-thresholded column heights, clouds = snapped drift + tick morph, animals = per-frame limb traces. Zero mesh staging/remesh; CPU passes vectors only, never revoxelizes.
2. Universal live extraction for dynamics: limb vector → thick-line trace (DDA/sphere-sweep inside the limb AABB) → neighbor-bit face emit, all in registers; grass/wave cells thresholded from noise then face-extracted the same way. Interior cells never emitted. Baked surface lists survive ONLY for integer-translatable static topology (cloud drift snapped to whole cells); everything articulating revoxelizes.
3. Occupancy-mip LOD: per-type 8³→4³→2³→1 OR-chain (~73B/type, conservative — coarser never holes); task picks mip by resident projected AABB. Quantized motion composes free (mips over grid cells).
4. Task broadcasts vectors, not matrices: task evals noise params + limb vectors once per batch, same-scalar broadcast <1c/cell; mesh threads trace + extract (no MAD blending, no per-cell trig). Culling payoff of the constraint: exact-normal kill is perfect and permanent (every face axis-aligned forever — no tilted-normal edge cases, no rotational AABB padding); AABBs pad by motion range only. Water keeps OIT pair-cancellation exactly.
5. Routing unchanged: grass alpha-tested opaque; clouds dithered-opaque vs OIT measured; shadows skip dynamics past near cascades; far collapses to billboard/0 via SetMeshOutputsEXT.
6. Uniforms event layer + precipitation bridge: coverage/amplitude/phase/time uniforms drive both sides at ~0 bound-stage cycles; coverage uniform spawns rain entities (EntityRegistry queue, bounded budget) → splash/foam flecks + swell-scaled amplitude. Cloud→water causality at event cadence, zero staging.

## Rotation, if allowed (pending decision — NOT in the plan above)

If voxels may rotate off-grid: restore matrix broadcast (1 rigid matrix or 3-4 bone sets per batch, SSBO table + resident index) and bone-MAD blending (~31c vs 60-80c SFU trig); rigid baked-face transforms return for all drifting/bobbing batches; live extraction narrows back to animals-only. Costs: exact-normal kill degrades to cone kill (rotated normals are no longer one vector); AABBs need rotational padding (bounding-sphere-ish, looser Hi-Z); OIT pair-cancellation threatened by tilted water faces (needs the virtual-entry/composite treatment from the underwater section). Revisit only if grid-snapped motion visibly pops on near hero content.
## Frame-budget shadow scheduling

Stutter is variance: one full cascade refresh spikes its frame no matter how refreshes amortize across cascades. Pace within the work, not just across it.

- Persistent queue of (cascade, meshlet-batch) items ordered by staleness × projected screen importance; each frame consumes until slider % × frame time (timestamp queries) is exhausted, then resumes mid-queue next frame. Meshlet batches are the pacing unit free from the mesh plan.
- In-place partial updates: a half-refreshed cascade reads as bounded staleness (latched basis + texel snapping + staleness padding already tolerate it); walk batches in spatial order for coherence. No double-buffering (cascade VRAM already large).
- Cascade 0 exempt — always refreshed whole, nearest pixels read tearing worst. Lag cap: force-full-refresh past a worst-staleness threshold (e.g. sun snap) so shadows converge instead of smearing time-of-day jumps.
- Composes with cascade caps (smaller queue) and per-slot sorted indices.
